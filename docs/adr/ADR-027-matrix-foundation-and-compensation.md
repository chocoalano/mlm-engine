# ADR-027: Matrix is an explicit numbered-slot overlay on generic placement, with its own paths, a network metric and source-entry compensation

## Status

Accepted — Phase 3.5.

## Context

A matrix plan limits how many direct children each member has in the paying structure — its width — and pays down that structure by depth. Generic placement (ADR-008) has no width and no positions, and binary (ADR-022) has exactly two sides named left and right. The matrix needs numbered slots up to a configured width, kept history-aware like the other trees, and compensation that is exact, explainable and correctable when a source is reversed later — without changing placement, binary or the commission core, and ready to be composed with other strategies later.

## Decision

- **An overlay on generic placement.** A matrix position enrols one generic placement edge in one of its parent's numbered slots. Generic placement is unchanged: no slot or width column, any number of children, placement rules as before. A third generic child of a parent whose two slots are full is simply generic-only. Only edges given a slot are in the matrix; a generic-only edge below a matrix member is not, until that edge is adopted itself. There is no left/right: slots are integers.
- **One network per program, width immutable.** `mlm_matrix_networks` holds one row per program (`UNIQUE(program_id)`) with its width, a PHP integer from 1 to 100 — never cast from a string, float or boolean. `MatrixNetworkManager::configure()` creates it, returns it again for the same width, and refuses another width: width is structure, not a commission setting, and there is no reconfiguration. A different topology would need an explicit rebuild, outside this design. Several networks per program, networks per plan version or per component are deferred.
- **Numbered slots.** `mlm_matrix_placement_positions` enrols an edge once (`UNIQUE(placement_edge_id)`) in slot 1 to the width; `UNIQUE(matrix_network_id, parent_id, slot)` is the capacity backstop. Slots are strict PHP integers. A slot is assigned once: adopting an edge again into the same slot returns its position, into another is refused; nothing moves and nothing is removed.
- **Explicit writes only.** `MatrixPlacementManager::place()` places through `PlacementGenealogy::place()` and assigns the slot in one transaction — a slot that cannot be taken leaves no generic edge, placement path, position or matrix path. `adopt()` enrols an existing edge. The caller always chooses parent and slot: there is no spillover, free-slot search, weak-leg or sponsor-following placement. Sponsorship is neither read nor written. Models are read-only through Eloquent.
- **Its own closure.** Matrix paths live in `mlm_genealogy_paths` under `tree_type` `matrix` (ADR-007), written through the shared closure mechanics and never mixed with sponsor, placement or binary paths. Rolling back migration 000032 deletes them with the positions.
- **Temporal and non-retroactive, as binary.** A placement takes its slot at its own moment; an adoption from now, never before the edge was placed — both floored by the moments already in the two parts they join, so paths stay monotonic. Adopting an edge attaches the member's existing matrix subtree from the adoption on; the subtree's internal paths keep their own moments. Earlier activity never becomes matrix activity.
- **Writes serialize on the program.** Every matrix write re-reads the edge and members under lock, then locks the program — the lock every genealogy write and the network's configuration take — and reads the network, the edge's position and the slot's occupant with locking reads before any plain read, so they see what writes before them committed. Racing placements into one slot leave one winner and a refusal with nothing of the loser's generic placement; into different slots, both succeed; racing adoptions of one edge resolve one position or refuse the other slot; racing first configurations make one network.
- **`MatrixGenealogy`, read-only.** Network, position, parent, child by slot, ancestors and descendants, as the matrix stands or stood at a moment. Every read starts from the stored member; a position that disagrees with its edge's parent, its program's network, its width or its program is refused (`CorruptMatrixPlacement`), never read. A member with a generic parent but no position is a matrix root. The matrix has no structural depth: depth limits belong to metrics and strategies, so compensation depth can change without rebuilding topology.
- **`matrix.network.volume`.** A plan-configurable metric (`type`, optional strict-integer `max_depth` counted from the member; unknown parameters refused): the net volume of the member's matrix descendants. The member's own volume, generic-only members, sponsorship and binary never count. It is the network metrics' own set-based query over the matrix paths (ADR-013): an entry counts in the period its own moment falls in, and only if its member was below the anchor at the activity's moment — for a reversal, the original's — so a later adoption never captures earlier activity. One query however large the network; exact, beyond 64 bits where the database widens its sums (ADR-010).
- **`matrix.fixed` and `matrix.proportional`.** Registered strategies of the existing commission component, with the same parameters and eligibility as the unilevel strategies (ADR-019, ADR-020): original entries of the volume and source type, effective in the run's range, at least the minimum, not reversed before `until` — a reversal at or after `until` belongs to a later range. For each entry the matrix line as it stood at the entry's moment pays each configured physical depth: no compression, a gap stays a gap, an ancestor adopted later earns nothing. Proportional awards are quantity × amount per unit, rounded per entry and depth through the shared calculator; zero earns nothing. Rules are refused. The ancestry is read set-based, a chunk of 500 entries at a time — one read of their matrix paths and one of the ancestors — never a query per entry. No state, no carry, no cycles.
- **Source-entry provenance, and clawback reused.** Each matrix commission comes from one original entry, keyed `volume-entry:<entry>:depth:<depth>`, and records `source_type` `volume-entry` and the entry's id (ADR-021). A later reversal is corrected by the unchanged `CommissionAdjustmentEngine::processVolumeReversal()` — cancelled before posting, reversed after — with no matrix-specific financial code. Traces keep the shared shape and add a `matrix` section (recipient and depth), and for the fixed strategy a `calculation` section.

## Consequences

- Matrix plans can be structured, measured and paid independently of sponsorship, generic placement and binary, and are ready to be composed with other strategies (Phase 3.6).
- Applications must configure a program's width before placing into the matrix, choose every slot themselves, and adopt existing placements explicitly: nothing is backfilled from generic placement.
- Spillover and automatic placement, cycling and re-entry, compressed matrices, completion bonuses, boards and resets, carry, pools, several networks per program, width changes and qualified or ranked recipients remain later designs.
